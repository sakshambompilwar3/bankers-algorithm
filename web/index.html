Dijkstra's Banker's Algorithm — OS Reference Guide

1. Historical Context

Formulated by Edsger W. Dijkstra (1965), Banker's Algorithm is a classic deadlock avoidance strategy. Named after a banking metaphor: a banker never allocates cash in a way that prevents satisfying the maximum borrowing needs of at least one customer who can finish and repay.

2. Silberschatz Mathematical Model

For n processes and m resource types:

  • Total Vector: Total physical instances per resource type.
  • Allocation Matrix (n × m): Currently allocated instances held by each process.
  • Maximum Demand Matrix (n × m): Maximum total claim declared by each process.
  • Need Matrix: Need[i][j] = Maximum[i][j] − Allocation[i][j]
  • Available Vector: Available[j] = Total[j] − Σ Allocation[i][j]

3. Safety Algorithm Steps

  1. Initialize Work = Available, Finish[i] = False for all i.
  2. Find index i where Finish[i] == False and Need[i] ≤ Work. If none, go to Step 4.
  3. Process Pi completes: Work = Work + Allocation[i], Finish[i] = True. Add Pi to Safe Sequence. Repeat from Step 2.
  4. If all Finish[i] == True → SAFE STATE. Otherwise → UNSAFE STATE.

4. Resource-Request Algorithm

  1. If Request[i] > Need[i] → Error (exceeds maximum claim).
  2. If Request[i] > Available → Process must wait.
  3. Tentatively allocate, run safety check. If Safe → Grant. If Unsafe → Rollback.
⚠ An Unsafe State ≠ Deadlock. An unsafe state means the OS cannot guarantee deadlock avoidance if all processes simultaneously demand their maximum claims. Banker's Algorithm refuses to enter unsafe states to prevent any possibility of deadlock.
